# ADR-0002 · 서드파티 의존성 0

```
상태: 채택
날짜: 2026-09-07
Agent: Alice (Architect)
```

## 맥락

참고용으로 오픈소스 엔진 10개를 받아 이 머신에서 빌드해 봤습니다.
**6개가 첫 빌드에서 막혔습니다.**

| 막힌 이유 | 어디서 |
|---|---|
| 한글 + 공백 경로에서 빌드 스텝이 쪼개짐 | LumixEngine |
| CMake 4.x 가 `cmake_minimum_required(<3.5)` 거부 | 다수 |
| Windows SDK 28000 의 `DirectX::Internal` 개명 | WickedEngine |
| CP949 로케일 → C4819 가 `/WX` 와 만나 에러 | 다수 |
| Python 3.13 에서 `distutils` 제거 | cocos2d-x |
| 병렬 빌드 레이스로 PDB 충돌 (C1041) | LumixEngine, panda3d |

**전부 서드파티나 생성 스텝에서 났습니다.** 엔진 자체 코드의 문제가 아니었습니다.

이 프로젝트는 "어느 컴퓨터에서든, 어떤 AI 세션에서든 기여할 수 있다"를 전제로 합니다.
첫 빌드가 막히면 그 전제가 무너집니다.

## 결정

**Phase 0 의 모든 코드에서 서드파티 의존성을 0으로 합니다.**

직접 쓴 것:

| 무엇 | 줄 수(대략) | 대안이었던 것 |
|---|---:|---|
| YAML 부분집합 파서 | 700 | yaml-cpp, rapidyaml, fkYAML |
| JSON 파서 | 400 | nlohmann/json, RapidJSON, simdjson |
| 테스트 프레임워크 | 200 | Catch2, doctest, GoogleTest |
| 문자열 포매터 | 150 | fmt, std::format |
| 진단 모델 | 200 | — |

합쳐서 약 1,650줄입니다.

## 대안과 버린 이유

### A. 헤더 온리 라이브러리만 vendoring 한다

`nlohmann/json` 과 `doctest` 를 저장소에 넣으면 네트워크 없이도 빌드됩니다.

**버린 이유:** 부분적으로 타당한 대안이었습니다. 버린 이유는 둘입니다.

1. **에러 메시지를 통제할 수 없다.** 이게 결정적입니다(→ ADR-0003).
   `nlohmann/json` 의 파싱 에러는 위치를 주지만 힌트를 못 줍니다.
   `"'positon' 은 없는 필드다. 'position' 을 뜻했는가?"` 같은 문장은 만들 수 없습니다.
2. **한번 열면 닫히지 않는다.** 헤더 온리 하나가 들어오면 다음엔 "이것도 헤더 온리인데"가 됩니다.

### B. CMake FetchContent 로 가져온다

가장 현대적인 방식입니다.

**버린 이유:** 네트워크가 필요합니다. 오프라인 환경, 방화벽 뒤, CI 캐시 미스에서 막힙니다.
"클론하면 바로 빌드된다"가 깨집니다.

### C. vcpkg / Conan

베이스 엔진이 vcpkg 를 씁니다.

**버린 이유:** 패키지 매니저 자체가 의존성입니다. 설치하고, 부트스트랩하고,
버전을 맞춰야 합니다. 새 기여자에게 요구하는 사전 준비가 늘어납니다.

## 결과

### 좋은 것

- `git clone && cmake && build` 가 정말로 그게 전부다. 설치 단계가 없다
- 파서의 진단 품질을 완전히 통제한다 (ADR-0003 이 이 위에 선다)
- 빌드가 빠르다. 전체 빌드가 20초 남짓
- 라이선스가 단순하다. MIT 하나
- 서드파티 CVE 대응, 버전 업그레이드, API 변경 추적이 없다

### 나쁜 것

- **우리가 유지해야 한다.** YAML 파서에 버그가 있으면 우리가 고친다
- **기능이 부족하다.** YAML 전체 명세를 지원하지 않는다.
  앵커를 쓰던 문서는 마이그레이션이 필요하다
- **성능이 최적이 아니다.** simdjson 은 우리 JSON 파서보다 훨씬 빠르다.
  → 콘텐츠 로딩이 병목이 되면 그때 다시 본다. 지금은 10개 문서에 74ms 다
- **바퀴를 다시 발명했다.** 1,650줄은 공짜가 아니다
- **이 결정은 영원하지 않다.** 물리 엔진, 오디오, 이미지 디코딩까지 직접 쓸 수는 없다

### 앞으로

Phase 1 에서 물리·오디오·이미지가 들어오면 서드파티가 필요해집니다.
그때의 규칙은 `Agents/Alice.md` 의 4가지 판단 기준입니다.

1. 없어도 되는가
2. 에러 메시지를 우리가 통제하는가
3. 모든 타깃 플랫폼에서 빌드되는가
4. 클론 즉시 빌드가 유지되는가

**"코어는 0, 주변은 신중하게"** 가 이 ADR 의 실질적 결론입니다.
