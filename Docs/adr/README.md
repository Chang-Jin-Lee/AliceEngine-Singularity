# 설계 결정 기록 (ADR)

큰 결정을 남깁니다. 코드는 결론만 남기고 과정을 지웁니다.
다음에 이 코드를 고칠 사람이 가장 알고 싶어 하는 것은 **이미 시도했다가 안 됐던 것**입니다.

## 언제 쓰는가

- 되돌리기 어려운 결정
- 대안이 여럿이었고 그중 하나를 골랐을 때
- "왜 이렇게 안 했어요?" 를 두 번 이상 듣게 될 것 같을 때

작은 결정은 코드 주석으로 충분합니다.

## 형식

```markdown
# ADR-XXXX · 제목

상태: 채택 | 대체됨(ADR-YYYY) | 폐기
날짜: YYYY-MM-DD
Agent: <역할>

## 맥락
무엇이 문제였는가

## 결정
무엇으로 정했는가

## 대안과 버린 이유
고려했다가 버린 것들. **버린 이유까지**

## 결과
좋은 것과 **나쁜 것 모두**. 대가 없는 결정은 없다
```

**"결과" 에 나쁜 것을 반드시 적으십시오.**
좋은 것만 적힌 ADR 은 다음 사람에게 아무 도움이 안 됩니다.
