# ADR-0001 · 게임플레이를 스크립트가 아니라 선언적 규칙으로

```
상태: 채택
날짜: 2026-09-07
Agent: Alice (Architect)
```

## 맥락

이 엔진의 목표는 "AI 가 다룰 수 있는 게임 엔진"입니다.

게임 엔진은 대개 게임플레이를 위한 실행 경로를 하나 갖습니다.
언리얼은 C++ + UHT + 블루프린트 VM, 유니티는 C#, godot 은 GDScript 입니다.

AI 가 이 구조에서 막히는 지점을 정리하면 이렇습니다.

1. **API 표면이 무한하다.** 어떤 함수가 있는지 목록을 뽑을 수 없다 → AI 가 이름을 지어낸다
2. **오류가 런타임까지 간다.** 컴파일이 통과해도 그 코드 경로를 밟아야 문제를 안다
3. **순서 의존이 숨는다.** 스크립트 A 가 상태를 바꿔 스크립트 B 의 동작이 달라진다
4. **확인에 에디터가 필요하다.** AI 가 자기 결과를 검증할 수 없다

## 결정

**게임플레이 스크립트 언어를 만들지 않습니다.** 대신 둘로 나눕니다.

```yaml
rules:
  - when: input.pressed("Jump") and physics.grounded    # 읽기만 하는 식
    do:
      - physics.impulse: { direction: [0, 1, 0], force: 6.5 }   # 상태를 바꾸는 동사
```

- `when:` — **부작용 없는 식.** 대입 불가. 상태를 읽기만 한다
- `do:` — **레지스트리에 등록된 유한한 동사 목록.** 각 동사는 인자 스키마를 갖는다

## 대안과 버린 이유

### A. Lua 를 임베딩한다

가장 흔한 선택이고 검증되어 있습니다.

**버린 이유:** 위 네 가지 문제를 하나도 해결하지 못합니다.
Lua 함수 목록을 기계가 읽을 수 있는 형태로 뽑을 방법이 없고, 오류는 여전히 런타임에 납니다.
그리고 AI 가 배워야 할 언어가 하나 더 늘어납니다.

### B. 블루프린트 같은 노드 그래프

시각적이고 언리얼에서 검증되었습니다.

**버린 이유:** 노드 그래프는 저장 형식이 결국 그래프 구조(노드 id, 핀 연결)입니다.
텍스트로 만들어도 AI 가 읽기 매우 어렵습니다.
그리고 diff 가 의미를 잃습니다 — 노드 하나를 옮기면 좌표가 전부 바뀝니다.

### C. C++ 컴포넌트를 직접 쓰게 한다 (베이스 엔진 방식)

베이스 엔진(AliceEngine-Optimization)이 이 방식입니다. 별도 DLL 로 스크립트를 빌드합니다.

**버린 이유:** AI 가 C++ 를 짜는 것 자체는 잘합니다. 문제는 **빌드 시간과 검증**입니다.
게임플레이 한 줄을 고칠 때마다 컴파일-링크-재실행이 필요하면 AI 의 반복이 너무 느립니다.

### D. 제한된 스크립트 언어를 직접 만든다

우리가 문법을 통제하니 정적 분석이 가능합니다.

**버린 이유:** 이것이 가장 진지하게 고민한 대안입니다.
버린 이유는 **결국 언어가 되기 때문**입니다. 루프가 필요해지고, 함수가 필요해지고,
그러면 다시 무한한 표현력과 런타임 오류의 세계로 돌아갑니다.

경계를 "식 + 동사"에 그어두면 그 미끄러짐이 일어나지 않습니다.
못 하는 것이 나오면 **언어를 확장하는 대신 동사를 추가**합니다.
그러면 AI 도 그 능력을 즉시, 문서와 함께 얻습니다.

## 결과

### 좋은 것

- `alice verbs --json` 하나로 **엔진이 할 수 있는 일 전부**가 나온다. AI 가 추측하지 않는다
- 실행 전에 전부 검사된다 — 동사 존재, 인자 타입, 이름 존재, 인자 개수
- **규칙 평가 순서가 결과에 영향을 주지 않는다.** 순서 의존 버그가 원천적으로 없다
- 컴파일이 없다. 문서를 고치면 즉시 반영된다
- diff 가 읽힌다. AI 의 변경을 사람이 리뷰할 수 있다
- 동사를 추가하면 검증·문서·자동완성이 전부 자동으로 따라온다

### 나쁜 것

- **표현력이 낮다.** 스크립트로 세 줄이면 될 것이 동사 추가를 요구할 수 있다
- **동사 폭발 위험.** 특수한 요구마다 동사를 추가하면 목록이 수백 개가 된다.
  그때는 "동사 목록이 유한해서 AI 가 파악할 수 있다"는 이점이 약해진다.
  → 완화: 동사에 태그를 붙였고 `alice verbs --tag` 로 좁힐 수 있게 했다
- **복잡한 상태 기계를 규칙으로 쓰면 읽기 어려워진다.**
  → 완화: 애니메이션은 별도의 상태 그래프 문서 타입을 두었다
- 성능. 규칙 평가는 컴파일된 코드보다 느리다.
  → 조건식은 AST 를 캐시하고, 규칙은 조건이 참일 때만 실행된다.
  → 그래도 부족하면 그 부분은 엔진 동사로 내린다

### 다시 볼 조건

동사가 150개를 넘거나, 콘텐츠 제작자가 "이건 규칙으로 못 쓰겠다"고 말하는 사례가
반복되면 이 결정을 다시 봅니다.
