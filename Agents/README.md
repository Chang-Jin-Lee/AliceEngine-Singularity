# 에이전트로 기여하기

이 저장소는 **서로 다른 컴퓨터에서, 서로 다른 AI 세션이, 서로를 모르는 채로** 기여하는 것을
전제로 만들어졌습니다. 그게 가능하려면 두 가지가 필요합니다.

1. 각자 **자기 영역만** 건드릴 것 — 그러면 충돌이 안 납니다
2. 각자 **왜 그랬는지** 남길 것 — 그러면 다음 사람이 이어받을 수 있습니다

이 폴더가 그 두 가지를 정의합니다.

---

## 시작하는 법

새 컴퓨터에서, 새 세션에서 이렇게 말하면 됩니다.

```
넌 이제부터 Seeho다.
AGENTS.md 와 Agents/Seeho.md 를 읽고,
Agents/Backlog/seeho/ 에서 작업 하나를 골라 진행하라.
```

> 도구별 자세한 시작 방법은 [`Docs/ONBOARDING.md`](../Docs/ONBOARDING.md) 에 있습니다.
> Codex 는 `AGENTS.md` 를, Claude Code 는 `CLAUDE.md` 를 자동으로 읽습니다.

또는 특정 작업을 지정해서:

```
넌 이제부터 Monday다. Agents/Backlog/monday/MON-02.md 를 진행하라.
```

에이전트는 그 다음 스스로:

1. `Agents/<이름>.md` 를 읽어 **자기 경계**를 확인하고
2. `Agents/Backlog/<이름>/` 에서 `상태: 대기` 인 작업 중 하나를 고르고
3. 그 작업 문서의 **완료 기준**을 만족시킬 때까지 작업하고
4. `Agent: <이름>` 을 밝힌 커밋/PR을 만듭니다

| 역할 | 한 문장 | 소유하는 디렉터리 |
|---|---|---|
| **Alice** | 무엇과 무엇이 만나도 되는지 정한다 | `Engine/*/[공개 헤더]`, `CMake/`, `Docs/ARCHITECTURE.md` |
| **Sidney** | 세계를 메모리에 올리고 굴린다 | `Engine/Runtime/`, `Engine/Doc/` |

경계가 겹치는 일은 반드시 생깁니다. 규칙은 하나입니다:

> **남의 영역의 공개 헤더를 바꿔야 하면, 먼저 Alice 앞으로 이슈를 연다.**
> 구현 파일(.cpp)은 자기 영역 안에서 자유롭게 고칩니다.

## 작업 문서의 모양

`Agents/Backlog/<에이전트>/<ID>.md` 하나가 작업 하나입니다.

```markdown
# MON-02 · D3D11 백엔드

상태: 대기            # 대기 | 진행중 | 리뷰 | 완료
크기: L               # S(반나절) | M(하루) | L(수일)
선행: 없음            # 이 작업 전에 끝나야 하는 다른 작업
담당: -               # 진행중이면 여기에 세션/사람 표시

## 무엇을
...

## 왜
...

## 완료 기준
- [ ] ...

## 건드리는 파일
...

## 건드리면 안 되는 것
...
```

**작업을 시작하면 `상태:` 를 `진행중` 으로 바꾸고 그것만 먼저 커밋하십시오.**
다른 컴퓨터의 다른 세션이 같은 작업을 잡는 것을 막는 유일한 장치입니다.

## 충돌을 피하는 실무 규칙

**브랜치 이름**

```
<에이전트 소문자>/<작업ID>-<짧은-설명>
예) monday/MON-02-d3d11-device
```

**커밋 메시지**

```
<타입>(<영역>): <한 줄 요약>

Agent: Monday (Graphics)
Task: MON-02

<본문 — 왜 이렇게 했는지>
```

타입: `feat` `fix` `perf` `refactor` `docs` `test` `build` `chore`

**한 PR = 한 작업.** 지나가다 발견한 다른 문제는 새 백로그 항목으로 만들고 넘어가십시오.
"김에 같이 고쳤다"가 리뷰를 가장 어렵게 만듭니다.

## 병합 전 반드시

어느 에이전트든 동일합니다.

```bash
./Scripts/verify.sh          # Windows: .\Scripts\verify.ps1
```

빌드(경고 0) · 테스트 · 샘플 검증 · 문서 정규화 · 생성물 최신 · 백로그 표를 전부 검사합니다.

Seeho 는 여기에 더해 성능 회귀를 봅니다.

## 에이전트가 저지르기 쉬운 실수

이 목록은 실제로 일어난 일이 생기면 계속 늘어납니다.

| 실수 | 왜 문제인가 | 대신 |
|---|---|---|
| 남의 모듈 공개 헤더를 조용히 고친다 | 다른 에이전트의 작업이 병합 시점에 깨진다 | Alice 앞으로 이슈를 연다 |
| 서드파티를 추가한다 | "클론하면 바로 빌드된다"가 깨진다 | PR 에서 먼저 합의 |
| 진단에 힌트를 안 넣는다 | AI가 스스로 못 고친다 | 코드·위치·힌트 셋을 채운다 |
| 로그를 문자열로 남긴다 | 기계가 못 읽는다 | `ALICE_LOG_*(채널, 이벤트).F(키, 값)` |
| 백로그 상태를 안 바꾸고 시작한다 | 다른 세션이 같은 걸 한다 | 먼저 `진행중` 커밋 |
| 테스트 없이 낸다 | 다음 사람이 못 건드린다 | 특히 진단 품질 테스트를 |
| PR의 "대안" 칸을 비운다 | 다음 사람이 같은 고민을 반복한다 | 버린 이유까지 적는다 |
