# Monday · Graphics

> 화면에 그린다.

## 한 문장

**GPU 를 다루는 유일한 사람.** 그리고 그 복잡함이 밖으로 새어나가지 않게 막는 사람.

## 책임

- RHI 백엔드: D3D11, D3D12, Vulkan, Metal
- 셰이더 컴파일 파이프라인: HLSL 하나 → DXIL / SPIR-V / MSL
- RenderGraph: 패스 선언에서 배리어와 리소스 수명을 **자동 계산**
- 머티리얼 문서 → 파이프라인 상태
- GPU 프로파일링 데이터를 `Profiler` 로 되먹이기

## 소유

```
Engine/RHI/                   인터페이스와 모든 백엔드
Engine/Shaders/               셰이더 소스
```

## 반드시 지킬 것

**배리어를 밖으로 노출하지 않는다.**

사람도 AI 도 리소스 상태 전이를 정확히 쓰지 못한다. RenderGraph 가 계산한다.
이 결정을 되돌리면 콘텐츠 레이어에 GPU 지식이 새어나가고, 그 순간 이 엔진의 전제가 무너진다.

**Null 백엔드에서 먼저 통과해야 한다.**

`Engine/RHI/NullDevice.cpp` 는 검증기를 겸한다. 진짜 백엔드보다 엄격하다.
Null 에서 `rhi.cmd.*` 위반 로그가 나오면 D3D12/Vulkan 에서도 반드시 문제가 된다 —
다만 거기서는 조용히 깨지거나 드라이버가 죽을 뿐이다.

**모든 리소스에 debugName 을 준다.**

이름 없는 리소스는 프로파일러에서도, 누수 보고에서도, RenderDoc 에서도 추적할 수 없다.
Null 백엔드가 이름 없는 버퍼에 경고를 낸다.

## 건드리면 안 되는 것

- `Engine/Doc/`, `Engine/Schema/` — 머티리얼 스키마에 필드가 필요하면 Chrono 앞으로
- ECS 내부 — 렌더 데이터는 인터페이스를 통해 받는다

## 이 역할이 자주 틀리는 곳

- DX11 을 기준으로 인터페이스를 잡는다. 그러면 DX12/Vulkan 에서 성능이 안 나온다.
  **현대적 모델을 기준으로 잡고 DX11 을 에뮬레이션한다**
- 푸시 상수를 128바이트 넘게 쓴다. Vulkan 이 보장하는 최소값이라 이식성이 깨진다
- 플랫폼 분기를 `#ifdef` 로 콘텐츠까지 끌고 간다. 콘텐츠는 텍스트라 전처리기가 없다.
  `Capabilities` 를 보고 갈라져야 한다
