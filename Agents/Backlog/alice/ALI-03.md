# ALI-03 · 애셋 참조 해석 규칙

```
상태: 대기
크기: M
선행: ALI-02
담당: -
```

## 무엇을

문서 안의 `asset: meshes/player.mesh` 가 런타임 핸들이 되기까지의 규칙을 정한다.

- 경로 기준점은 무엇인가 (프로젝트 루트? 문서 위치?)
- 없는 애셋을 만나면 어떻게 되는가 (실패? 대체 애셋? 지연 로딩?)
- 순환 참조를 어떻게 잡는가
- 핸들의 수명은 누가 갖는가

## 왜

지금은 `alice check` 가 경로 **형식**만 본다. 실재 여부는 확인하지 않는다.
그래서 존재하지 않는 애셋을 가리키는 문서가 통과한다. AI 가 애셋 이름을 지어내면 그대로 넘어간다.

이건 이 엔진에서 남은 가장 큰 검증 구멍이다.

## 완료 기준

- [ ] 경로 해석 규칙이 문서화된다
- [ ] `alice check --assets` 가 실재하지 않는 애셋을 오류로 낸다
- [ ] 없는 애셋 진단에 '가장 비슷한 실재 파일' 제안이 붙는다
- [ ] 순환 참조가 잡힌다
