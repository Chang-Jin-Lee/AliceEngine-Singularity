# 백로그 작업을 잡을 때

## 순서

```bash
python Scripts/backlog.py           # 전체 현황
```

1. 자기 역할 디렉터리에서 `상태: 대기` 인 것을 봅니다
2. `선행:` 이 전부 `완료` 인 것 중에서 고릅니다
3. **고른 즉시** 상태를 바꾸고 그것만 커밋합니다

```
상태: 대기   →  상태: 진행중
담당: -      →  담당: <세션 표시>
```

```bash
git commit -m "chore(backlog): SID-02 진행중

Agent: Sidney (Runtime)
Task: SID-02"
```

**이것이 여러 컴퓨터가 같은 작업을 잡는 것을 막는 유일한 장치입니다.**
빼먹으면 두 세션이 같은 코드를 서로 다르게 고쳐 병합에서 충돌합니다.

## 상태

| 상태 | 뜻 |
|---|---|
| `대기` | 아무도 안 잡았다 |
| `진행중` | 누군가 작업 중이다. 건드리지 마라 |
| `리뷰` | 작업이 끝나 PR 이 열려 있다 |
| `완료` | 병합됐다 |

`진행중` 이 7일 이상이면 버려진 것일 수 있습니다. 커밋 로그를 확인하십시오.

## 새 작업을 만들려면

```markdown
# <ID> · <제목>

```
상태: 대기
크기: S | M | L
선행: <다른 ID 또는 없음>
담당: -
```

## 무엇을
## 왜
## 완료 기준
- [ ] ...
## 건드리는 파일
## 건드리면 안 되는 것
```

**"왜" 를 비우지 마십시오.** 작업을 잡은 사람이 판단이 필요할 때 돌아오는 곳입니다.

**"완료 기준" 은 검증 가능해야 합니다.** "잘 동작한다" 가 아니라
"`alice check Samples` 가 0오류" 처럼 확인할 수 있는 문장으로 쓰십시오.

지나가다 발견한 문제는 **여기에 항목을 만들고 넘어가십시오.**
"김에 같이 고쳤다" 가 리뷰를 가장 어렵게 만듭니다.

## 표 갱신

작업을 추가하거나 상태를 바꾸면 `Agents/README.md` 의 표도 맞춰야 합니다.

```bash
python Scripts/backlog.py --check    # 어긋났으면 알려준다
```
