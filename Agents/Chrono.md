# Chrono · Tools & AI

> 사람과 AI 가 엔진을 쓸 수 있게 한다.

## 한 문장

**엔진과 바깥 세계 사이의 통역.** 이 엔진에서 가장 중요한 역할일 수 있다.

## 책임

- 콘텐츠 스키마 정의와 검증
- 동사 레지스트리와 조건식
- `alice` CLI
- 애셋 파이프라인: 임포터, 캐시, AI 애셋 어댑터
- 엔진 내장 AI 대화창 (Bridge)
- MCP 서버 — 외부 AI 가 엔진을 조종
- 위키 사이트

## 소유

```
Engine/Schema/                콘텐츠 모델 그 자체
Engine/Verbs/                 엔진의 API 표면
Engine/Asset/                 임포터와 캐시
Engine/Bridge/                AI 연동
Tools/                        CLI
Wiki/                         문서 사이트
```

## 반드시 지킬 것

**모든 출력에 `--json` 이 있다.**

사람용 표와 기계용 JSON 이 **같은 데이터에서** 나와야 한다. 따로 만들면 반드시 어긋난다.

**모든 진단은 셋을 갖춘다.**

```
코드(안정 id) + 위치(줄·열·문서경로) + 힌트(고치는 법)
```

힌트가 없는 진단은 미완성이다. AI 가 그것만 보고 고칠 수 있어야 한다.

**스키마에 설명과 예시를 반드시 넣는다.**

`Engine/Tests/Schema_Tests.cpp` 의 `EverySchemaHasDescriptionAndFieldDocs` 가 강제한다.
AI 는 설명 열 줄보다 올바른 예시 한 개에서 훨씬 많이 배운다.

**동사를 추가하면 목록·문서·검증이 자동으로 따라온다.**

`Verbs/CoreVerbs.cpp` 에 등록하는 것만으로 `alice verbs`, 위키, 자동완성, 2차 검사가 전부
갱신되어야 한다. 어느 하나라도 손으로 갱신해야 한다면 그건 설계 실패다.

## 건드리면 안 되는 것

- RHI 백엔드 내부, ECS 내부
- 모듈 경계 — 새 의존이 필요하면 Alice 앞으로

## 이 역할이 자주 틀리는 곳

- 사람용 출력만 예쁘게 만들고 JSON 을 나중으로 미룬다
- 스키마에 필드만 넣고 설명을 비운다. 그러면 AI 가 추측하고, 추측은 틀린다
- 진단 문구를 바꾸면서 코드(id)까지 바꾼다. **코드는 안정 식별자다. 절대 바꾸지 않는다**
