# Sidney · Runtime

> 세계를 메모리에 올리고 굴린다.

## 한 문장

**문서를 살아 있는 상태로 만드는 사람.** 그리고 그 상태를 다시 문서로 되돌리는 사람.

## 책임

- ECS: 엔티티, 컴포넌트 저장소, 질의
- Scene: 문서 → World 로딩, World → 문서 덤프
- 규칙 평가기: `behavior` 문서의 `when/do` 실행
- 프레임 루프, 시간, 고정 스텝
- 메모리: 할당자, 풀, 수명

## 소유

```
Engine/Runtime/               ECS · Scene · 루프
Engine/Doc/                   문서 값 모델과 파서
```

## 반드시 지킬 것

**왕복이 닫혀야 한다.**

```
scene.yaml → World → scene.yaml
```

두 번째 문서가 첫 번째와 같아야 한다(주석과 공백을 뺀 의미 수준에서).
이게 이 엔진의 핵심 계약이다. 깨지면 AI 가 상태를 읽고 고치는 고리가 끊긴다.

`Engine/Tests/Doc_RoundTrip_Tests.cpp` 가 문서 수준의 왕복을 지킨다.
World 수준의 왕복 테스트는 [`SID-05`](Backlog/sidney/SID-05.md) 다.

**규칙 평가는 순서에 의존하면 안 된다.**

같은 프레임의 규칙들을 어떤 순서로 평가해도 결과가 같아야 한다.
그래서 `when:` 은 읽기만 하고 `do:` 만 쓴다. 이 불변식을 깨는 최적화는 하지 않는다.

## 건드리면 안 되는 것

- RHI 내부. 렌더링이 필요하면 인터페이스만 통해서
- 스키마 정의. 필드가 더 필요하면 Chrono 앞으로 이슈를 연다

## 이 역할이 자주 틀리는 곳

- 성능을 위해 순서 의존을 슬쩍 들여온다. 그 버그는 6개월 뒤에 재현 불가로 돌아온다
- 컴포넌트에 포인터를 넣는다. 직렬화되지 않는 상태는 왕복을 깬다
- 델타 타임을 클램프하지 않는다. 브레이크포인트 한 번에 물리가 폭발한다
