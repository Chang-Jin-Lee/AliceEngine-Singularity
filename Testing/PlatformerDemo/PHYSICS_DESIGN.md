# 최소 플랫폼어 물리 — 설계 제안

작성: Codex, 2026-09-17. 상태: 사용자 승인 후 구현. 실제 결과·범위는 README.md와 VERIFICATION.md 참조.

## 목표와 선택

외부 라이브러리 없이 좌우 이동, 중력, 점프, 바닥 착지, 벽·천장 충돌을 구현한다. 일반 강체 대신 회전하지 않는 사각형 캐릭터가 고정 사각형 지형을 이동하는 모델을 사용한다. XY 평면, Y 위쪽, 미터·초 단위다. 기존 Transform 미리보기는 물리 모드를 선택하지 않은 씬에서 유지한다.

대안은 Box2D 자체 도입, 자체 범용 강체 솔버, 플랫폼어 전용 충돌 처리다. 첫 번째는 외부 의존성 0 원칙 변경이 필요하며, 두 번째는 회전·접촉·마찰·적층 안정성까지 구현 범위가 커진다. 세 번째를 추천한다. 대가는 상자 쌓기, 회전 강체, 경사면, 이동 발판을 첫 구현에서 제공하지 않는 것이다. 정적 지형과 캐릭터 사이의 충돌만 지원하고 캐릭터 상호 충돌은 지원 목록에서 명시적으로 제외한다.

## 계산

- 1/60초 고정 스텝. 렌더 프레임 시간은 누적하고 한 프레임의 처리 스텝 수를 제한한다. 버린 시간은 구조화 로그로 기록한다.
- 속도에 중력을 먼저 적용한 뒤 이동한다. 수평 이동·점프 정책과 충돌 해결은 분리한다.
- 이동 경로 전체를 검사하는 swept AABB로 얇은 바닥 관통을 방지한다. 가장 이른 충돌까지 이동하고 충돌 법선 방향 속도만 제거한 뒤 남은 이동을 처리한다.
- 동시 충돌은 안정 ID와 정해진 축 우선순위로 처리한다. 충돌 반복 횟수는 제한하고 한도 도달 시 남은 이동을 중단해 관통을 방지한다.
- 초기 겹침은 제한된 밀어내기를 시도하고 해결 불가 시 위치·힌트가 있는 진단으로 시작을 거부한다. 허용 오차·접촉 간격은 문서화된 상수로 일관되게 적용한다.
- 발 아래 접촉으로 grounded를 계산한다. 벽·천장을 접지로 취급하지 않는다. 점프는 눌림 전이 한 번만 소비하고 접지 상태에서만 허용한다. 물리 스텝이 없는 렌더 프레임에서도 눌림을 보존한다.
- 정적 지형의 AABB 트리를 씬 로드 시 구성한다. 이동 경로 주변만 후보로 조회한다. 매 스텝 트리를 재생성하지 않는다. 데이터와 작업 버퍼는 연속 배열을 사용하고 초기화 이후 반복 할당을 피한다.

## 데이터와 사용자 확장

물리 코어는 에디터·키보드·YAML에 의존하지 않는다. 호출자는 지형, 캐릭터 상태, 이동 요청을 전달하고 위치·속도·접지·접촉 결과를 받는다. 별도 어댑터가 문서를 읽고 ECS Transform에 결과를 반영한다.

1. 콘텐츠 사용자: 스키마가 검증하는 전용 2D 캐릭터 설정에서 수평 속도·점프 속도·중력 배율을 조절한다. 씬 중력과 기존 box collider 크기·중심·Transform을 재사용한다. 기존 rigidbody를 완전 지원하는 것처럼 해석하지 않는다. 새 컴포넌트와 물리 모드의 정확한 필드·기본값은 구현 계획에서 확정하고 CLI 스키마로 노출한다.
2. 엔진 확장 사용자: 작은 C++ 물리 제공자 인터페이스를 구현해 동일 입출력 계약 아래 충돌 처리 또는 이동 정책을 교체한다. 정적 링크 등록으로 시작하며 DLL 로딩은 추가하지 않는다. 사용자 제공자 예제와 계약 테스트를 함께 제공한다. 사용자 제공자 상태의 저장·복원 계약과 지원 기능도 명시한다.

사용자 설정은 코드 실행이 아닌 검증되는 데이터다. 임의 수식으로 새로운 물리 법칙을 작성하는 DSL은 이번 범위에 포함하지 않는다. 일반 behavior 실행기는 기존 SID-04의 별도 작업이며 이 구현만으로 모든 등록 동사가 실행된다고 설명하지 않는다.

NaN/Inf, 음수 크기, 범위 초과 설정, 지원하지 않는 회전·형상·계층·물리 옵션은 조용히 무시하지 않고 진단한다. 로드 실패는 기존 실행 상태를 보존한다. 에디터의 실행 중 편집은 물리 상태·지형 인덱스를 함께 갱신하거나 지원 불가 진단으로 거부해야 한다.

## 연결과 검증

Runtime 코어, 스키마, 에디터 Play 입력, 테스트·빌드 목록 연결이 필요하다. 문서·실험 씬·벤치마크 결과는 사용자 요청대로 Testing 아래에 둔다. 기존 CubePlayground 동작은 회귀 테스트로 보존한다. Testing/PlatformerDemo에서 A/D 좌우, Space 점프가 동작하고 실제 창의 Play 검사까지 수행한다.

필수 테스트: 자유 낙하, 착지 후 정지, 반복 점프, 공중 점프 거부, 눌림 보존, 벽·천장, 모서리 동시 충돌, 얇은 벽 고속 이동, 시작 겹침, 가장자리 낙하, 프레임 분할 변화, 긴 정지 후 재개, 잘못된 문서의 위치·힌트, 사용자 제공자 교체, Stop 원본 복구. 핵심 계산을 의도적으로 깨뜨렸을 때 관련 테스트가 실패하는 것도 확인한다.

성능은 전수 검색 기준 구현과 같은 결과를 내는지 비교한 다음 측정한다. 100/1,000/10,000개 정적 지형과 1/100개 캐릭터의 희소·밀집 배치를 사용한다. 고정 시드·입력, 준비 구간, 반복 횟수, CPU·빌드 설정, 스텝 평균/p95, 후보 수, 정확 충돌 검사 수를 기록한다. 벤치마크 중 씬 생성 비용과 스텝 비용을 분리한다. 벽시계 성능을 CI 통과 기준으로 쓰지 않는다. Box2D와 동등한 기능·조건으로 비교하지 않았다면 우월성을 주장하지 않는다.

프로파일 존은 Physics.Step 및 Physics.Query를 사용한다. 최종 검증은 전체 verify, Testing 콘텐츠 검사, 실제 창 smoke, 기능 테스트, 성능 결과 기록을 포함한다.

## 참고 자료와 차용 범위

- [Box2D simulation](https://box2d.org/documentation/md_simulation.html): 고정 스텝, ID와 데이터 중심 저장. 코드를 복사하지 않고 설계 원리를 참고한다.
- [Box2D character mover](https://box2d.org/documentation/md_character.html): 캐릭터 제어를 일반 강체와 분리. 해당 구현은 실험적 capsule 기반이며 여기의 AABB 방식과 동일하지 않다.
- [Box2D dynamic tree](https://box2d.org/documentation/group__tree.html): 공간 인덱스로 충돌 후보를 줄이는 원리. 첫 구현의 지형은 정적이므로 정적 트리로 단순화한다.
- [Godot character body](https://docs.godotengine.org/en/stable/tutorials/physics/using_character_body_2d.html): 사용자 이동 제어와 충돌·미끄러짐 결과 분리.
